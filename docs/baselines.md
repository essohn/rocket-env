# 베이스라인 측정 기록

등급 컷을 눈감고 정하지 않기 위한 기록이다. 라운드를 새로 만들거나 난이도를
조정할 때마다 `scripts/measure_baseline.py`로 다시 재고 여기에 덧붙인다.

측정 조건: 평가 40 에피소드, 시드 `10000..10039`, `deterministic=True`.
학습은 SB3 `DQN("MlpPolicy")`, `net_arch=[256, 256]`, `buffer_size=200000`,
`learning_starts=5000`.

## 왜 이 파일이 필요한가

**모든 정책이 같은 점수를 받는 환경도 모든 테스트를 통과한다.** 실제로 이
저장소는 165개 테스트가 전부 통과하는 상태에서, 무행동 정책이 실패 상한
40점 중 36.6점을 받고 학습된 DQN이 그보다 **낮은** 점수를 받는 환경을
만들어냈다. 단위 테스트도, exploit 회귀 테스트도 그것을 잡지 못했다 —
"꼼수가 이기지 못한다"는 검증했지만 "실력이 이긴다"는 아무도 검증하지
않았기 때문이다. 변별력은 재봐야 안다.

## 학습 예산에 대한 경고

**10만 스텝으로 재면 안 된다.** 그 예산에서는 모든 프리셋에서 DQN이 성공률
0%이고 무행동보다 낮은 점수를 받는다. 실제로 이 사실 때문에 "환경이 학습
불가능하다"는 잘못된 결론에 도달해 보상을 두 번 재설계했다.

학생이 Colab에서 30~60분 돌리는 것은 **50만~100만 스텝**에 해당한다.
측정은 그 예산으로 해야 한다. 10만 스텝은 코드가 도는지 확인하는
스모크 테스트용이지 성능 측정용이 아니다.

## n=1 측정의 함정 — 학습 시드도 재봐야 안다

**같은 설정, 같은 100만 스텝 예산으로 두 번 돌렸더니 성공률 12.5%/점수
33.46과 성공률 0%/점수 −1.60이 나왔다.** 차이는 SB3 `DQN` 생성자에 넘긴
학습 시드뿐이었다 — 평가 시드 40개는 고정돼 있었지만 학습 시드는 매번
난수였다. 즉 아래 "측정 결과"의 각 행은 **n=1** 샘플이다. 환경이
학습 가능하다는 판단도, 그 위에서 설계한 6라운드 커리큘럼도 이 n=1
숫자 하나에 의존하고 있었다.

이건 채점에도 직결된다. 학생 200명의 DQN 에이전트를 이 환경으로 채점하는
데, 시드만 바꿔도 성공률이 0%에서 12.5%로 뛴다면 성적이 실력이 아니라
운을 재는 것이다.

**그래서 `scripts/measure_baseline.py`는 이제 `--seeds N` (기본 3)으로
여러 학습 시드를 독립적으로 돌리고, 각 실행의 점수/성공률을 한 줄씩
찍은 뒤 평균·최솟값·최댓값과 "평균 DQN − 무행동" 분리도를 함께
보고한다.** 앞으로의 측정은 전부 이 방식으로 다시 재고, 여러 시드
없이 나온 숫자는 신뢰하지 않는다.

아래 "측정 결과"의 기존 표들은 전부 **n=1** (학습 시드 하나) 측정이다.
지우지 않고 남겨둔다 — 언제 무엇을 쟀는지의 기록 자체가 가치가 있다.
다만 그 숫자들을 근거로 결론을 내리지는 말 것.

### 2026-07-22 — `landing-basic`, 학습 시드 5개 × 100만 스텝

| 정책 | 점수 | 성공률 |
|------|------|--------|
| 무행동 | 0.38 | 0.0% |
| 무작위 | −0.77 | 0.0% |
| DQN seed 0 | 3.58 | 2.5% |
| DQN seed 1 | −0.16 | 0.0% |
| DQN seed 2 | −0.31 | 0.0% |
| DQN seed 3 | 80.56 | 40.0% |
| DQN seed 4 | **159.30** | **87.5%** |
| **평균** | **48.59** | **26.0%** |

범위 −0.31 ~ 159.30. 무행동 대비 평균 분리 **+48.21**.

**환경은 학습 가능하다.** 시드 4가 87.5% 성공에 159.30점으로, 손으로 짠 고전
제어기(100%, 201.2점)에 근접했다. DQN 이 이 문제를 풀 수 있다는 것은 확정이다.

**그러나 결과 분포가 이봉형이다.** 다섯 시드가 두 무리로 갈리고 중간이 없다 —
실패군 3개(0~2.5%)와 성공군 2개(40%, 87.5%). 에이전트가 착륙 행동을
**발견하느냐 못 하느냐**의 문제이고, 발견하면 잘한다. 희소 보상 탐색 문제의
전형적 양상이다.

#### 채점에 주는 함의

한 번만 학습하면 **약 40% 확률**로 작동하는 에이전트를 얻는다. 단발 제출을
채점하면 성적이 실력이 아니라 학습 시드를 잰다.

기존 제출 워크플로(다회 제출 + 체크포인트에서 최고 모델 선택)가 이 문제를
흡수한다:

| 학습 횟수 | 최소 한 번 성공할 확률 |
|-----------|------------------------|
| 1회 | ~40% |
| 3회 | ~78% |
| 5회 | ~92% |

**"여러 번 돌려서 가장 좋은 모델을 제출하라"는 요령이 아니라 필수 절차이며,
학생에게 명시적으로 안내해야 한다.** 모르면 한 번 돌리고 자기 코드가 틀렸다고
생각하며 시간을 버린다. RL 실무에서 시드를 여러 개 돌리는 것이 표준이라는
점을 가르칠 기회이기도 하다.

### 2026-07-22 — shaping 분리 이후 (`landing-basic`, 시드 5개 × 100만 스텝)

| 정책 | 점수 | 성공률 |
|------|------|--------|
| 무행동 | 0.00 | 0.0% |
| 무작위 | −0.33 | 0.0% |
| DQN seed 0 | 64.92 | 27.5% |
| DQN seed 1 | 143.19 | 72.5% |
| DQN seed 2 | 113.88 | 60.0% |
| DQN seed 3 | 191.94 | 97.5% |
| DQN seed 4 | 187.28 | **100.0%** |
| **평균** | **140.24** | **71.5%** |

무행동 대비 평균 분리 **+140.24**.

**이봉형 분포가 사라졌다.** 다섯 시드가 전부 학습했고 실패군이 없다. 최악이
27.5%, 최고가 100% 성공으로 연속 분포를 이룬다. 직전 측정(평균 26.0%,
3/5가 0~2.5%)과 비교하면 평균 성공률이 **2.7배**다.

**이 비교는 오히려 보수적이다.** 이 측정은 Task 16 이 초기 각속도를 추가해
개루프 정책을 구조적으로 봉쇄한 **뒤**의 것이다. 즉 더 어려워진 과제에서
나온 숫자다.

#### 무엇을 바꿨는가

직전까지 shaping 총합의 상한은 `-Φ(s₀)` = 0.98~2.25 였고 종료 보상은
0 / ≤40 / ≥132 였다. **밀집 신호가 리턴의 1% 미만**이라 탐색을 전혀 안내하지
못했다. 그렇다고 가중치를 올리면 맴돌기가 이득이 됐다 — 타임아웃 점수가
`0 + (Φ(s_T) − Φ(s₀))` 라, 20배로 키우면 호버가 20점을 받아 착륙을 시도하다
실패한 쪽을 이겼다. **exploit 저항성을 사느라 학습 신호를 팔고 있었다.**

해법은 shaping 총합을 정확히 0으로 만드는 것이었다. 종료 스텝에서
`Φ(종료) := 0` 으로 두면 망원경 합이 `-Φ(s₀)` 가 되고, 종료 시 `+Φ(s₀)` 를
더하면 상쇄된다. 그러면:

- 리더보드 점수 = 종료 보상 − 연료 비용. shaping 은 흔적을 남기지 않는다
- 학습에는 스텝마다 밀집 신호가 그대로 간다
- **가중치를 얼마로 올려도 점수가 바뀌지 않는다** — 500배에서도

`test_return_is_independent_of_shaping_weights` 가 이 성질을 직접 단언한다.
가중치를 20배(`shaping_w_dist` 1.0 → 20.0 등)로 올린 결과가 위 표다.

#### 채점에 주는 함의

한 번 학습으로 최악 27.5%, 평균 71.5% 성공을 얻는다. 직전 측정에서 필요했던
다회 제출 완화책은 이제 **필수가 아니다.** 여전히 권할 만하지만(최고 시드와
최악 시드의 차이가 27.5%p 대 100%), 한 번 돌려서 0% 를 받는 학생은 없다.

점수 범위 64.92~191.94 는 리더보드로 쓰기에 충분히 벌어져 있고, 손으로 짠
고전 PD 제어기(100%, 201.2점)가 여전히 천장을 열어둔다.

|--------|------------------|-------------|--------|
| 1 `landing-basic` | — | **71.5%** | 27.5 / 60 / 72.5 / 97.5 / 100 |
| 2 `landing-attitude` | 초기 자세 ±30° | **42.5%**\* | 85.0 / 0.0 / 42.5 |
| 3 `landing-descent` | 고도 450m, 진입 −50 | **5.0%**\* | 0.0 / 0.0 / 15.0 |
| 4 `landing-wind` | 상수 바람 8 m/s | 측정 예정 | |
| 5 `landing-gust` | 돌풍 + 연료 55 | 측정 예정 | |
| 6 `catch` | 젓가락 포획 | 측정 예정 | |

`landing-attitude` 상세: 무행동 0.00 / 0%, 무작위 0.13 / 0%,
DQN 평균 점수 82.46 (범위 −0.49 ~ 162.50), 분리 +82.46.

#### 라운드가 올라갈수록 시드 운의 비중이 커진다

`landing-basic` 은 다섯 시드가 **전부** 학습했다(최악 27.5%). `landing-attitude`
는 세 시드 중 **하나가 0%** 다. shaping 분리가 탐색 문제를 완화했지만 없애지는
못했다 — 과제가 어려워질수록 성공 궤적을 우연히 만날 확률이 낮아지므로
당연한 결과다.

`landing-descent`는 절벽이었다 — 세 시드 중 둘이 0%, 나머지도 15%. 원인은
"진입 속도"를 축으로 오인한 것이었다: 고도 200→450m는 2.25배 상승인데,
항력 시상수가 약 5초라 450m에서는 초기 하강속도와 무관하게 거의 항상
종단속도(−49.5 m/s)에 도달한다. 즉 초기 vy는 거의 영향이 없고 **고도**가
실제 난이도 축이었는데, 그 축을 한 라운드에서 2.25배나 올려버린 것이다.

**학생 안내는 라운드별로 달라야 한다.** 1라운드는 한 번 학습해도 되지만,
2라운드부터는 **여러 번 돌려 최고 모델을 제출**하는 것이 실질적으로 필수다.
이건 요령이 아니라 RL 실무의 표준이며, 측정 없이는 알 수 없는 사실이다.

\* **2026-07-22 이후 superseded.** 위 `landing-attitude`(42.5%)와
`landing-descent`(5.0%) 두 행은 옛 `x_range`(±50)와 옛 `landing-descent`
초기 조건(고도 450m, vy −50~−40)으로 측정한 숫자다. 이번 수정으로
`x_range`는 여섯 프리셋 전부 ±80으로 고정되었고, `landing-descent`
계열(`landing-descent`/`landing-wind`/`landing-gust`/`catch`)의 진입
조건은 고도 300m·vy −30으로 완화되었다. 두 변경 다 실제 학습 난이도에
영향을 주므로, 이 숫자들을 앞으로 다시 잴 숫자와 직접 비교해서는 안 된다.
지우지 않고 남기는 이유는 baselines.md 전체의 원칙과 같다 — 언제 무엇을
쟀는지의 기록 자체가 가치가 있다.

## 재측정 방법

```bash
uv pip install -e ".[sb3]"
uv run python scripts/measure_baseline.py --preset landing-basic --steps 1000000 --seeds 5
```

프리셋을 바꾸거나 `reward.*`를 건드린 뒤에는 반드시 다시 잰다. `--seeds`는
최소 3 이상으로 — 학습 시드 하나짜리 측정(n=1)은 이 문서에 결과로
기록하지 않는다.
